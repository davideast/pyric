# Hosted sandbox and live-mode ownership

This records the ownership and browser-artifact portion of the implementation
contract. It does not establish that all owners have their final implementation.
The [support contract](hosted-sandbox-live-mode-support.md) now states the
initial admission, durability, retention, performance, and lifetime policies.
Its configuration/scenario declaration check is partial; gate 0B still needs
complete metadata validation and executable scenario bindings.

| Initial target selection | `serve/entries/init-payload.ts`, `serve/entries/worker-runtime.ts` | Resolve initialization before choosing a transport. A failed hosted selection cannot create a different local store. SDK operation families do not select hosting. |
| Application lifetime | App registry and `serve/entries/app-client.ts` | Explicit app deletion releases its client. Transport interruption does not delete the app. |

Count pending service/tool operations from those records by physical port and logical relayed client, refusing operation 257 before registration/send. Retain Firestore subscription messages for restoration on the same logical port; never retain one-shot operations for replay. Release failed posts and local cancellations. Preserve the distinction between unsent work, uncertain outcomes, and deletion. Host/remote queue budgets, other service restoration and failed subscription posting remain unfinished. |
| SDK reference construction | `pyric/firestore/refs.ts`, `pyric/firestore/snapshots.ts`, `serve/worker/client/firestore-reference.ts`, shared value identity registry, and host query resolution | Modular document methods live outside the Admin error-translation proxy. Removing or replacing a converter keeps a usable modular reference and does not mutate the original. The factory registers both backing and modular reference identities for query capture. Decoded references borrow the receiving SDK owner or client port. Host query references use the selected database. Stored values carry reference identity without owning a connection. |
| Physical browser socket | `serve/worker/client/websocket-connection.ts` | Own socket generations, attach deadlines, reconnect backoff, the private resume grant and physical connectivity observers. Its optional ClientPort observation method reports attachment/loss without exposing transport selection to service callers. Ignore replaced-socket callbacks. In-page execution observes its existing RtdbConnectionLifecycle rather than adding another online-state owner. Both adapters suppress unchanged deliveries and use existing snapshot construction and listener registries. The in-page registration joins the existing app cleanup owner before its synchronous initial callback. Normal .info/connected and parent .info listeners follow explicit controls; unsubscribe, onlyOnce and deleted-app refusal are reviewed across all three paths. Parent metadata queries use the shared pure projection and retain only the previous selected rows for unchanged-result suppression. The in-page registry records the query scope so off preserves a sibling parent listener. Scalar metadata queries, remaining constraints, reset/import, separate get semantics and complete host online/offline behavior remain required. |
| Admission and authority | `bridge/server/peer.ts`, `bridge/server/bridge.ts` | Bind incoming work to its admitted consumer and current generation. Reserve the hosted authority. A supplied session ID is not authorization. |

The shared identity result carries refusal through both socket callers and targeted MCP tools. Rejected updates preserve the existing record and listeners; native serializer exhaustion is contained at this admission boundary. No new connection, timer or subscription owner is introduced. |
| Retained hosted worker sessions | `bridge/server/worker-sessions.ts` | Own host-issued resume grants, logical consumer identity, connection leases and 60-second interruption expiry. Keep grants out of consumer presence. Socket detach retains identity; explicit deletion retires the grant; mount shutdown closes the owner. Full admission, stale-generation, expiry and resource-bound proofs remain required. |
| Import validation | `pyric/sandbox/persistence/import-bundle.ts` and `serve/worker/host/connection.ts` | Decode and validate replacement input before mutation. Reuse the persistence checksum and value decoder; leave recovery-reader quarantine unchanged. Both host transports return validation errors. Complete raw legacy/schema validation and transactional all-service replacement remain required. |
| Public remote pending operations | `remote/index.ts` | The existing pending map owns correlation, deadlines and event-loop holds. Refuse operation 257 before adding a record or timer; success/error replies, timeout, send failure and disposal remove records through their existing paths. No second counter or replay queue is introduced. Aggregate byte admission and complete reply validation remain open. |
| Hosted remote relay | `serve/hosted/runtime.ts` | Translate published remote operations and subscriptions into the existing host's per-consumer queue. Each admitted consumer owns its port, auth session and cleanup; the adapter forwards results and errors and marks remote provenance. Its queue admits at most 256 pending service/tool operations and releases each slot in finally; control/subscription messages do not consume those operation slots. Legacy operation routing binds the admitted identity in `bridge/server/peer.ts`. Aggregate queued bytes, subscription admission, unbounded event relay and complete service/reconnect/lifetime accounting remain required. |
| Checkpoint storage and restored subscriptions | `serve/worker/host/connection.ts`, `serve/worker/host/subscriptions.ts`, `serve/worker/host-context.ts`, and `serve/hosted/runtime.ts` | Hosted checkpoints reuse `pyric/sandbox/checkpoints/directory`; SharedWorker retains its record backend. Auth changes select only app-session intents. Unsubscribe and port cleanup remove retained intent. Hosted restore awaits persistence and refuses execution while unhealthy. Corrupt checkpoint validation, full metadata fidelity, and import/reset restoration remain required. |

| Shared host execution | `serve/worker/host/`, `serve/worker/serve-init.ts` | Own execution, per-consumer ordering, identities, and accepted-work cleanup across host runtimes. Keep sandbox behavior out of transport shells. |

Shared preparation resolves against the preceding projected state and validates deletion sequences before mutation. Rules methods use original existence and final projected state. Invalid/non-finite inputs and complete inbound validation remain open. |

| Modular transaction document reads | `pyric/firestore/transactions.ts`, `pyric/firestore/snapshots.ts`, `pyric/firestore/state.ts`, and worker client snapshot/read adapters | Each callback receives a modular adapter over a fresh backing transaction. Paths in the table are relative to `packages/cli/src` unless prefixed with
`pyric/`. A new responsibility needs a declared owner; it must not be hidden in
an SDK operation or appended to a generic manager merely because that manager
already has access to the required state.

The process lock relies on SQLite's [single-writer and immediate-transaction contract](https://www.sqlite.org/lang_transaction.html), through the built-in [Node 22.15 driver](https://nodejs.org/download/release/v22.15.0/docs/api/sqlite.html) or [Bun driver](https://bun.com/docs/runtime/sqlite). It adds no application schema or persistence format. Keep its connection alive and its pathname intact for the entire ownership lifetime.

## Browser leaf budgets

These are raw minified ESM bytes emitted by the installed esbuild version with
`platform: browser`, bundling enabled, and no Node shims. Each entry is built
independently, so the live entry includes its real Firebase SDK dependencies.
The budgets apply to these leaves, not to the entire served app, Studio, or
the existing in-page fallback bundle.

| Entry relative to the repository root | Initial measured bytes | Maximum bytes |
| --- | ---: | ---: |
| `packages/cli/src/serve/worker/client.ts` | 48,248 | 98,304 |
| `packages/cli/src/serve/worker/client/websocket-connection.ts` | 4,573 | 16,384 |
| `packages/cli/src/serve/worker/client/rtdb-listeners.ts` | 12,887 | 32,768 |
| `packages/pyric/src/firestore/internal/value-codec.ts` | 12,260 | 24,576 |
| `packages/cli/src/serve/entries/live/firestore.ts` | 387,843 | 524,288 |

Run `bun packages/cli/scripts/check-browser-boundaries.ts <entry> <max-bytes>`
after building workspace packages. The report names modules contributing bytes
to the output. The check rejects sandbox/rules engine contributors, CLI host
contributors, imports left outside the inspected bundle, and exceeded budgets.
Node imports fail the browser build instead of receiving shims.

The RTDB listener leaf has its own 32 KiB ceiling, declared before measuring
the query-projection integration. The older worker barrel does not re-export
these listeners, so its report cannot measure their cost. The shared
`pyric/database/internal/query-projection.ts` owns pure ordering, bounds and
window projection for both backend queries and browser-local metadata.
It imports only types and owns no data store, rules evaluator or resources.
The projection also owns its query types; the backend query module retains
its existing exports through a re-export. A scoped import audit includes
type-only edges and finds no cycle among the backend facade, projection and
JSON value definitions. This does not establish the whole repository graph;
the browser boundary checker and its engine exclusions are unchanged.

Shared Firebase errors, app-handle deletion state, value wrappers, browser
attribution helpers, and the two value identity registries are intentional
browser dependencies. Their directory/file exceptions are explicit in the
checker. Tree-shaken dependencies do not count as shipped engine code; the
remaining source import/cycle audit must still examine those dependencies.

Changing a budget or boundary requires an explained contract or dependency
change and new measurements. A failing gate alone does not justify changing
its limit. These artifact checks do not complete U4's source ownership,
transport-selection, and cycle requirements.
