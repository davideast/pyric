# Parallel oracle assignments for Arcade, satisfy.md and Pyric

Start with four owners. Give Tally Slate's ordered fold, Arcade Yacht's score, and Pyric's Firestore atomic batch one owner each. Give the fourth owner the shared discovery and validation work. These exercise three different ways to know an answer: a native component with an independently worked example, a stock cloud rule that still needs an exact live witness, and an existing authenticated production SDK receipt. They can all make progress before the next live capture.

This is a source and evidence inventory. The sources are Arcade `66e14d4`, satisfy.md main `f8c555be`, Pyric main `a7ade6a70`, the local policy compiler `d386b3596`, and the local Arcade oracle `22575fec0`. The six satisfy.md experiment snapshots appear below. The existing Arcade command reads its frozen corpus. The general per-claim discovery layout is still a proposal. ## Integration and live work

1. **Freeze the inputs each agent reads.** Pin the complete rules/import closure, model/tape, schema, trusted inputs and evaluator version. Each agent writes a single new claim or probe subtree. A repeat capture appends a uniquely named observation. Use private build output, ports, histories and SDK identities. Compute indexes and reports on read. Keep shared contract definitions, adapters, registry allocations, compiler changes and coverage baselines under explicit ownership. If a dependency changes, replay all dependent probes.
2. **Separate authority for every result.** An accepted native trace answers a gameplay question. A deployed SDK attempt answers what a specific release allowed. The gateway can establish refusal before append. A compiler can establish placement or name the standalone requirement. Preserve each answer, operation and provenance. A release can remain unevidenced while standalone conformance passes. Count a shared primitive once, then score each separately witnessed composition at its own scope.
3. **Schedule captures by the resource they can change.** Existing receipts can replay offline concurrently. Production variants changing the same Firestore release queue through deployment, verified propagation, SDK attempt, server readback, restoration and verification. Apply the analogous rule to one RTDB instance and one Storage bucket. Lock the companion data/target as well for cross-service cases. Native Pyric and the experimental Arcade capturer have distinct lock mechanisms, so funnel both through one capture owner until they share a scheduler. Multiple document prefixes cannot isolate a release swap. On one deliberately fixed release, concurrent operations are eligible only when every read and write path and fixture dependency is isolated.
4. **Gate expansion on a merged run.** Discover all three pilot claims no matter their merge order. The two Tally orderings must separate. The atomic case must detect the wrong sibling projection. The Yacht claim must show as awaiting live evidence until its complete proposals and readbacks exist. After new evidence is admitted, replay stock, candidate and a discriminating mutation against the same cases. Disputed answers remain visible outside verified coverage. The 21 frozen counter decisions must still replay. Then open Sokoban score, Checkers midpoint, the two Lava Run tapes, RTDB ancestor writes and Storage metadata as separate assignments. Introduce a new shared adapter only when a named probe needs it.

### Reproducing the inventory

Use `git ls-tree -r <rev>` in each repo. In Arcade, enumerate `games/*/src/rules.test.ts`, then follow the Firestore, Storage and RTDB entry points and imports. In satisfy.md, compare path/blob pairs ending in `.policy` at the six named refs, and inspect main's RTDB assembly separately. In Pyric, count immediate `.ts` scenario files beneath each engine excluding `index`, `load` and `types`, then join exact scenario IDs to observation filenames. Count the two direct test roots by `.test.ts` and the rules artifacts by suffix and blob ID. Embedded policies, bench fixtures, examples and composed artifacts inform the assignments. A source count alone earns no conformance credit.
