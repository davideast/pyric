# Fix campaign: parallel streams that do not collide

The fix phase starts only after the evidence has landed as pins. Every stream
proves itself by removing pins; none may weaken one.

## 1. Stream plan

Group findings by root cause and by the files the fix must touch. Write a table
before anyone starts:

| Stream | Findings | Owns (may edit) | Must not edit | Depends on |
|---|---|---|---|---|
| S0 evidence | — | corpus, observations, registry, baselines, pin tables | engine source | — |
| S1 DSL output | … | `src/rules/rtdb/constraints/*` | grammar, simulator | — |
| S4 simulator | … | `grammar/simulator.ts`, `simulation/handler.ts` | validator | S0 |
| … | | | | |

Rules for the table:

- **Disjoint ownership.** No two streams own the same file. Shared generated files
  (scorecards, baselines, node counts, score pins) are owned by the evidence
  stream and regenerated by the integrator, never hand-edited by two streams.
- **Exceptions are written down.** When a stream needs a file it does not own (a
  one-token export, a test site that encoded non-production behavior), it asks;
  the coordinator approves on the board, naming the file and the reason.
- **Waves.** Streams with no dependency run at once; dependent streams stack on
  their base branch.
- **One worktree per stream** under a gitignored directory; never work in the
  main checkout.

## 2. Each stream works test-first against the pins

1. Remove the pin for one case. Run the conformance test: it must fail (red).
2. Change the engine until the case passes (green), with the production
   observation as the answer key.
3. Typecheck and run the single test file often; the full gates once at the end.
4. A test elsewhere that asserted the old, non-production behavior changes only
   with a citation (observation field or deploy rejection) in a comment at the
   site, and only after the coordinator approves. Keep the test's intent: change
   what it asserts about the wrong behavior, add a case for anything the change
   would otherwise leave uncovered.
5. Commit with a body that names the findings, the red→green evidence, and either
   regenerated conformance evidence or a `Conformance-Exempt:` trailer.

## 3. Review on two axes

Each stream is reviewed by an agent that did not write it:

- **Standards** — does the change follow `docs/code-conventions.md`, AGENTS.md
  boundaries, file ownership?
- **Spec** — does it fix exactly the findings assigned, match the cited
  observations, and leave nothing half-done?

The reviewer re-runs red→green itself: check out the base's source with the
stream's tests and confirm they fail, then the stream tip and confirm they pass.

## 4. Integrate

One integrator merges approved streams in dependency order onto a branch from
`origin/main`:

- after each merge, regenerate shared evidence (`compat:conformance`,
  `compat:rules-score`) and run the gates;
- resolve conflicts in generated files by regeneration, not by picking a side;
- after the last merge, consolidate: fold duplicated helpers into one module,
  remove pins whose dependency has now landed, fix review notes deferred as
  non-blocking;
- final gates, plus every finding's repro re-run against the integrated build —
  all must print FIXED.

## 5. Downstream check

If an app or package prompted the campaign, pack the integrated build
(`bun pm pack` per package) and run that consumer's own equivalence or
regression gate against it in a throwaway copy, without committing tarballs or
touching its checkout.
