# Four-hour goal prompt

Use up to four hours to decide whether Pyric should promise multiple guarded returns inside a bounded `for...of`. Start with the locked loop trial on `experiment/policy-for-of-contract` and its compiler revision in `experiments/policy-oracle/trials/for-of/lock.json`. Work in a separate worktree. Run the existing replay first.

Use the loop author’s original two-guard chess policy as the motivating case. It returns true when it reaches the destination and false when it finds an occupied intermediate square. The one-guard rewrite already passes the hidden positions. The question is whether accepting the author’s natural first version buys enough clarity at an acceptable semantic and Firestore cost.

1. Freeze reference answers before changing the compiler. Cover an adjacent move, six clear squares, a blocker on the first or sixth square, and an occupied destination. Add a case where both guards match and the first decides. Add paired missing-field cases where an earlier return skips the read and where evaluation reaches the same read. Use Arcade for chess truth. Label evaluation order and error propagation as proposed language guarantees.
2. Prototype two ordered guarded returns through Pyric’s public opt-in parser and evaluator. Preserve finite-list bounds, input immutability, and refusal before iteration on overflow. Compare the original two-guard policy and its one-guard rewrite on identical inputs. Keep Tally’s ordered, single-accumulator policy as a regression control. Record exact diagnostics for unsupported forms.
3. Link the generated chess helper into the complete Arcade ruleset. Compare it with the qualified handwritten helper using identical authenticated SDK writes to isolated live Firestore. Record release digests, full documents and server versions before and after every attempt, and restoration of the prior release. Qualify skipped and reached errors through a hosted write where the distinction changes the verdict. Record local expression counts separately from hosted observations.
4. Reverse the guards and force eager evaluation of the second guard. Require independent tests to identify each mutation’s first wrong verdict. Replay the existing suites and rescore both saved author submissions. If a fresh-author comparison fits, use equal briefs and hidden cases and report first-edit correctness separately from performance.

Deliver one replay command, the two policy forms side by side, and a decision for one guard, two ordered guards, and broader loop bodies. For each, say what an author may rely on, which runtime enforces it, and which case would change the decision. Keep accumulation standalone unless separately qualified. Leave general statements, nesting, and map updates for later. Stop when the evidence settles the question or the cap expires.
